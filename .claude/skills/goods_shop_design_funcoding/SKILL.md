# 굿즈샵 디자인 톤 가이드

굿즈샵의 모든 화면이 **한 가게처럼** 보이게 하는 규칙이다. 페이지를 새로 만들거나 고칠 때 아래 다섯 가지 원칙을 지키고, 끝나기 전에 맨 아래 체크리스트로 확인한다.

1. 모든 페이지에서 같은 색·같은 버튼 모양
2. 폰에서도 잘 보이는 충분히 큰 글씨
3. 손가락으로 누르기 쉬운 큰 버튼
4. 모바일에서 자연스러운 반응형
5. 같은 의미는 같은 표현

디자인의 기준은 `css/style.css` 하나다. 새 스타일이 필요하면 **`style.css`에 클래스로 추가**하고, HTML에 `style="..."`로 색·크기를 직접 쓰지 않는다. (여백 한두 줄 같은 배치 조정만 예외)

## 금지 규칙 — 어떤 페이지에서도 하지 않는다

아래 세 가지는 예외 없이 금지한다. 페이지를 새로 만들거나 고칠 때 가장 먼저 확인한다.

### 금지 1. 이모지·아이콘 사용 — 글자로만 표시한다
- **금지:** 이모지(🛍️ 🛒 🎉 😢 🔒 ⏳ ☕ 등), 기호 아이콘(⚠ ✓ ✔ ✕ ★ ♥ → ›), 아이콘 이미지·SVG 아이콘, 아이콘 글꼴(Font Awesome, Material Icons 등), CSS `content`로 넣는 기호
- 화면 글자뿐 아니라 **DB 값**(상품 `emoji` 같은 칸), **알림(`toast`)·`confirm` 문구**, **`<title>`**에도 쓰지 않는다.
- 대신 이렇게 한다:

| 이모지·아이콘을 쓰고 싶은 곳 | 글자로 표시하는 방법 |
|---|---|
| 로고 | `굿즈샵` 글자만 |
| 상품 사진이 없을 때 | `.product-thumb` 칸에 **상품 이름 글자**를 크게 표시 (배경은 `--primary-soft`) |
| 장바구니 담기 알림 | "장바구니에 담았어요" |
| 결제 완료 / 실패 / 확인 중 화면 | 제목 글자만: "결제를 완료했어요" / "결제하지 못했어요" / "결제를 확인하고 있어요" |
| 관리자 전용 안내 | "관리자만 볼 수 있는 페이지예요." |
| 잘못 입력한 칸의 경고 | 빨간 글자로 이유만: "이메일 형식이 올바르지 않아요." |
| 삭제·닫기 버튼 | `삭제`, `닫기` 글자 버튼 (✕ 금지) |
| 다음·자세히 | `다음`, `자세히 보기` 글자 (→ › 금지) |

- **허용하는 기호는 딱 네 가지:** 수량 버튼의 `+` `−`(글자 기호이며 `aria-label`로 뜻을 적는다), 금액 계산의 `×`, 날짜·항목 구분의 `·`
- 외부 결제위젯(토스) 안의 아이콘은 우리가 만든 것이 아니므로 예외.

### 금지 2. 페이지마다 다른 색 — 정해진 색만 쓴다
- **금지:** `:root` 변수에 없는 색, 색 코드(`#…`, `rgb()`, `hsl()`, `red` 같은 색 이름)를 HTML·JS·CSS 규칙 안에 직접 쓰기
- **금지:** 특정 페이지만을 위한 색(예: 관리자 페이지만 보라색, 이벤트 페이지만 주황색). 같은 역할은 **모든 페이지에서 같은 색**이다: 주요 버튼 = `--primary`, 삭제·오류 = `--danger`, 결제 완료 = `--success`…
- **금지:** 페이지 HTML 안의 `<style>` 태그, `style="color: …"` / `style="background: …"`. 스타일은 `css/style.css` 한 곳에만 둔다.
- **금지:** 새 색 변수를 마음대로 추가하기. 정말 필요하면 사용자에게 먼저 묻고, 추가한 뒤 이 스킬의 색 표를 갱신한다.
- 그라데이션은 상품 썸네일(`--primary-soft` → `--accent-soft`) 하나만 쓴다.

### 금지 3. 같은 의미에 다른 단어 — 하나의 단어로만 쓴다
- **금지:** 같은 뜻을 페이지마다 다르게 쓰기. 예) 저장 버튼을 어떤 페이지는 "저장", 어떤 페이지는 "확인", 또 다른 페이지는 "완료"로 쓰기
- 한 뜻에는 [용어집](#용어집--이-표현만-쓴다)의 **한 단어만** 쓴다. 용어집에 없으면 먼저 용어집에 추가하고, 그 뒤로는 모든 페이지에서 그 단어만 쓴다.
- 역할별로 말 모양을 고정한다:

| 역할 | 정해진 모양 | 예 | 금지 |
|---|---|---|---|
| 버튼 | **"~하기"** (하는 일) | 저장하기, 결제하기, 조회하기 | 확인, 완료, OK, 네, 저장 / 저장하기 섞어 쓰기 |
| 상태 표시 | **"~ 완료 / ~ 대기 / ~ 실패"** | 결제 완료 | 완료됨, 성공, Done |
| 끝난 뒤 알림 | **"~했어요"** | 저장했어요, 장바구니에 담았어요 | 저장 완료!, 성공했습니다 |
| 되묻기 | **"~할까요?"** | 삭제할까요? | 정말요?, 계속하시겠습니까? |

- 짧게 쓸 자리(표 안, 장바구니 줄)라도 단어를 바꾸지 않는다. 예외는 용어집에 이미 적힌 짧은 버튼 이름(`삭제`, `로그인`, `로그아웃`, `회원가입`)뿐이다.

## 기준 예시 — 모든 페이지는 이 스타일을 따른다

### 좋은 버튼 예시
- 손가락으로 편하게 누를 만큼 크게
- 모서리는 부드럽게 둥근 모양
- 색은 화면에서 가장 잘 보이게

```html
<button class="btn btn-block" type="submit">결제하기</button>
```

| 요구 | 이렇게 만든다 (`.btn`에 이미 들어 있음) |
|---|---|
| 손가락으로 누르기 편하게 | 높이 **48px 이상**(`min-height: var(--tap-main)`), 좌우 여백 20px. 폰에서는 `.btn-block`으로 폭 전체 |
| 부드럽게 둥근 모서리 | `border-radius: 10px` (카드는 14px, 배지는 알약 모양) |
| 화면에서 가장 잘 보이는 색 | 진한 파랑 `var(--primary)` 배경 + 흰 글씨 `var(--on-color)`, 글씨 16px·굵기 600. **글씨와 배경의 대비 4.5:1 이상**(지금 5.4:1). 파란 버튼은 화면에 하나뿐이라 눈이 바로 간다 |

- 보조 행동은 회색 `.btn-ghost`, 삭제는 빨간 `.btn-danger`로 **모양은 같고 색만** 다르게 한다.
- **하지 않는다:** 아이콘만 있는 버튼, 밑줄 글씨 버튼, 높이 30px대 작은 버튼, 모서리가 각진 버튼, 연한 색 배경에 흰 글씨(잘 안 보임), 한 화면에 파란 버튼 여러 개

### 좋은 입력칸 예시
- 입력칸 위에 무엇을 적는 칸인지 라벨 표시
- 잘못 입력하면 빨간색으로 알려주기

```html
<form id="my-form" novalidate>
  <div class="field">
    <label for="email">이메일</label>
    <input id="email" type="email" autocomplete="email" placeholder="you@example.com">
    <span class="hint">주문 확인에 필요해요.</span>
  </div>
  <button class="btn btn-block" type="submit">조회하기</button>
</form>
```
```js
const emailInput = document.getElementById("email");
const email = emailInput.value.trim();
// 잘못되면 칸이 빨개지고 칸 바로 아래에 빨간 글자로 이유가 나온다. 다시 입력하면 저절로 사라진다.
if (!setFieldError(emailInput, !email ? "이메일을 입력해 주세요." : !isEmail(email) ? "이메일 형식이 올바르지 않아요." : "")) {
  emailInput.focus();
  return;
}
```

| 요구 | 이렇게 만든다 |
|---|---|
| 위에 라벨 표시 | 모든 입력칸은 `.field` 안에서 **`<label for>` → `<input>` → `.hint`(필요할 때)** 순서. 라벨은 16px 굵게. `placeholder`는 입력 예시일 뿐 라벨을 대신하지 않는다 |
| 잘못 입력하면 빨간색 | `setFieldError(input, "이유")`(`js/common.js`) 사용 → 칸 테두리·배경이 빨갛게(`aria-invalid="true"`), 칸 **바로 아래**에 빨간 굵은 글자로 이유 문구(`.field-error`, 경고 기호 없이 글자만). 오류 문구는 용어집 말투: "~을 입력해 주세요." / "~ 형식이 올바르지 않아요." |

- 폼에는 `novalidate`를 붙여 브라우저 기본 말풍선 대신 이 방식으로만 알려 준다.
- 검사는 **[제출] 버튼을 눌렀을 때** 한 번에 하고, 잘못된 첫 칸으로 커서를 옮긴다(`focus()`).
- 칸 하나의 문제가 아닌 오류(예: "이메일 또는 비밀번호가 맞지 않아요.")는 버튼 위 `.error`에 보여 준다.
- **하지 않는다:** 라벨 없이 placeholder만, 경고 아이콘 붙이기, `alert()`로 오류 알리기, 폼 맨 위에만 오류 문구, 빨간색만 바꾸고 이유는 안 쓰기

## 1. 같은 색 · 같은 버튼 모양

### 색은 변수로만 쓴다
`style.css`의 `:root` 변수만 사용한다. `#1b64da` 같은 색 코드를 새로 쓰지 않는다. 색을 바꿔야 하면 변수 값을 바꾸고, **글씨와 배경의 대비가 4.5:1 이상**인지 확인한다.

| 변수 | 쓰임 |
|---|---|
| `--primary` / `--primary-dark` / `--primary-soft` | 주요 버튼(흰 글씨 대비 5.4:1), 눌렀을 때, 안내 박스(`.notice`) 배경 |
| `--text` / `--muted` | 본문 글씨 / 보조 설명 글씨 |
| `--bg` / `--surface` / `--line` | 페이지 배경 / 카드 배경 / 구분선 |
| `--success(-soft)` | 결제 완료 |
| `--warn(-soft)` | 결제 대기 |
| `--danger(-soft)` | 결제 실패, 오류 문구, 잘못 입력한 칸, 삭제 버튼 (대비 5.3:1) |
| `--danger-dark` | 삭제 버튼을 눌렀을 때 |
| `--accent-soft` | 상품 썸네일 배경 그라데이션 |
| `--on-color` | 색 배경(버튼, 알림, 숫자 배지) 위의 흰 글씨 |
| `--radius` (14px) / `--shadow` | 카드 모서리 / 카드 그림자 |
| `--tap` (44px) / `--tap-main` (48px) | 누를 수 있는 것의 최소 크기 / 주요 버튼 높이 |

버튼·입력칸 모서리는 `10px`, 카드는 `var(--radius)`, 배지는 둥근 알약 모양(`20px`)으로 통일한다.

### 버튼은 이 세 가지만
| 클래스 | 언제 | 예 |
|---|---|---|
| `.btn` (파란색) | 그 화면의 **가장 중요한 행동 1개** | 결제하기, 로그인, 조회하기 |
| `.btn .btn-ghost` (회색) | 보조 행동 | 쇼핑 계속하기, 비회원으로 결제하기, 로그아웃 |
| `.btn .btn-danger` (빨간색) | 되돌릴 수 없는 행동 | 삭제 |

- 한 화면(또는 한 카드) 안에 파란 `.btn`은 **하나만** 둔다.
- 폭 전체를 채울 때는 `.btn-block`을 붙인다. 모바일 결제·로그인 버튼은 항상 `.btn-block`.
- 좁은 자리(표 안, 장바구니 줄, 상단 메뉴)에는 `.btn-small`을 함께 붙인다. 높이 44px, 글씨 16px로 기준은 그대로 지킨다.
- 밑줄 글씨처럼 생긴 버튼은 만들지 않는다.

### 공통 부품을 재사용한다
새로 만들기 전에 이미 있는 것을 쓴다.

| 부품 | 클래스 |
|---|---|
| 흰 박스 | `.card` |
| 상태 표시 | `statusBadge(status)` 함수 (`.badge-paid` / `-pending` / `-failed`), 비회원 표시 `.badge-guest` |
| 입력칸 묶음 | `.field` > `label` + `input` + `.hint` ([좋은 입력칸 예시](#좋은-입력칸-예시)) |
| 칸별 오류 표시 | `setFieldError(input, "이유")` / 이메일 검사 `isEmail(value)` |
| 폼 전체 오류 문구 | `.error` |
| 파란 안내 박스 | `.notice` |
| 빈 화면 | `.card.empty` > `<p>안내 문장</p>` + 행동 버튼 1개 |
| 폭 좁은 페이지 | `.container.container-medium`(720px, 목록) / `.container-narrow`(480px, 폼·결과) |
| 카드 아래 여백 | `.stack` |
| 폼 아래 보조 안내 | `.form-foot` > `.hint` + `.btn-ghost.btn-block` |
| 잠깐 뜨는 알림 | `toast("...")` |
| 금액 / 날짜 | `won(n)` / `formatDate(iso)` (`js/common.js`) |

## 2. 폰에서도 잘 보이는 글씨

| 용도 | 최소 크기 |
|---|---|
| 본문, 버튼, 메뉴, 표 내용 | **16px** |
| **입력칸(`input`, `select`)** | **16px** — 16px보다 작으면 아이폰이 화면을 강제로 확대한다 |
| 보조 설명(`.hint`, 날짜, 배지) | **14px** |
| 주문번호 같은 코드 글씨 | 13px (이보다 작게 하지 않는다) |
| 페이지 제목 `h1` | 26px (모바일 24px) |
| 금액 합계 | 18px 이상, 굵게 |

- 줄 간격은 `line-height: 1.5` 이상.
- 회색 보조 글씨(`--muted`)는 설명에만 쓰고, 꼭 읽어야 하는 정보(금액, 오류, 결제 상태)는 `--text` 또는 상태 색으로 쓴다.
- 글씨 굵기: 제목·금액 700~800, 버튼·라벨 600, 본문 400.

## 3. 손가락으로 누르기 쉬운 버튼

- 누를 수 있는 모든 것(버튼, 메뉴 링크, 수량 +/−, 체크박스 영역)은 **높이와 폭 최소 44px**.
- 주요 버튼(`.btn`)은 **높이 48px 이상**(`min-height: 48px`), 글씨 16px.
- 누를 수 있는 것끼리는 **8px 이상** 떨어뜨린다.
- 수량 조절 `+` / `−` 버튼도 44×44px 이상.
- 버튼 글씨는 **무엇이 일어나는지** 쓴다: "확인" 대신 "결제하기", "조회하기".
- 처리 중에는 버튼을 `disabled`로 막아 두 번 눌리지 않게 한다.

## 4. 모바일에서 자연스러운 반응형

- 모든 페이지 `<head>`에 `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- **가로 스크롤이 생기면 안 된다.** 좌우 여백은 16px(`.container`의 padding).
- 기준 폭은 `820px` 하나만 쓴다(`@media (max-width: 820px)`). 그보다 좁으면:
  - 두 칸 배치(예: `.cart-layout`)는 **한 칸으로 쌓는다**. 결제 정보가 아래로 온다.
  - 결제·로그인 같은 주요 버튼은 `.btn-block`(폭 전체).
  - 상단 메뉴는 줄바꿈되어도 겹치지 않게 한다(`flex-wrap`).
- 상품 목록 같은 카드 격자는 `grid-template-columns: repeat(auto-fill, minmax(220px, 1fr))`처럼 **폭에 따라 자동으로** 줄어들게 한다. 고정 폭(`width: 600px` 등)을 쓰지 않고 `max-width`를 쓴다.
- 표(`table`)는 반드시 `.table-wrap`으로 감싸 표 안에서만 가로로 밀리게 한다.
- 이미지는 `max-width: 100%`.
- 확인할 폭: **375px(폰)**, 768px(태블릿), 1280px(PC).

## 5. 같은 의미는 같은 표현

### 말투
- 모든 문구는 **해요체**: "~해요", "~해 주세요", "~할까요?"
- 오류는 **무엇이 안 됐는지 + 어떻게 하면 되는지**: "이메일 형식이 올바르지 않아요." / "주문번호와 이메일을 다시 확인해 주세요."
- 실패 문구는 "~하지 못했어요"로 통일한다. ("실패했습니다", "오류 발생" 사용 안 함)
- 영어 오류 메시지를 그대로 보여 주지 않는다. `errorText(err, "~하지 못했어요. 잠시 후 다시 시도해 주세요.")`(`js/common.js`)를 쓰면 우리 서버가 만든 한국어 문구는 그대로, 영어는 기본 문구로 바뀐다.
- 개발 용어(RPC, 세션, 토큰, 익명 로그인 등)는 화면에 쓰지 않는다.

### 용어집 — 이 표현만 쓴다
| 의미 | 쓰는 표현 | 쓰지 않는 표현 |
|---|---|---|
| 지우기 확인 | **삭제할까요?** | 지우시겠습니까?, 정말 삭제하시겠어요? |
| 지우기 버튼 | **삭제** | 제거, 지우기, X |
| 담기 | **장바구니 담기** / 담은 뒤 "장바구니에 담았어요" | 카트, 추가하기 |
| 장바구니 | **장바구니** | 카트, 쇼핑백 |
| 결제 버튼 | **결제하기** | 구매하기, 주문하기, 결제 진행 |
| 결제 상태 | **결제 완료 / 결제 대기 / 결제 실패** | 승인, 완료됨, 미결제, 오류 |
| 결제 기록 | **결제 내역** (회원) / **비회원 주문 내역** | 구매 내역, 주문 목록 |
| 비회원 조회 | **비회원 주문 조회** | 주문 확인, 주문 검색 |
| 로그인 관련 | **로그인 / 로그아웃 / 회원가입** | 로그 인, 사인인, 가입하기 |
| 회원이 아닌 사람 | **비회원** | 게스트, 손님, 익명 |
| 번호 | **주문번호** | 주문 ID, 오더 번호 |
| 금액 | **결제 금액**, 합계 금액은 **총 결제 금액** | 가격 합계, 총액 |
| 불러오는 중 | **불러오는 중…** | 로딩중, 잠시만요 |
| 목록이 비었을 때 | **아직 ~이 없어요.** / **~이 비어 있어요.** | 데이터가 없습니다 |
| 관리자 전용 | **관리자만 볼 수 있는 페이지예요.** | 권한이 없습니다 |
| 돌아가기 | **홈으로**, **장바구니로 돌아가기** | 뒤로, 메인으로 |
| 성공 알림 | **~했어요** (예: 결제를 완료했어요) | ~되었습니다 |
| 저장 버튼 / 저장 후 알림 | **저장하기** / **저장했어요** | 저장, 확인, 완료, 적용 |
| 창·안내 닫기 | **닫기** | 확인, X, 취소(닫기 뜻일 때) |

- 금액은 항상 `won()`으로 `12,000원` 형식, 날짜는 `formatDate()`로.
- 되돌릴 수 없는 행동(삭제, 주문 취소 등)은 먼저 `confirm("삭제할까요?")`처럼 **용어집 표현 그대로** 묻는다.
- 새 표현이 필요하면 이 용어집에 먼저 추가하고 그 표현만 쓴다.

## 새 페이지 뼈대

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>페이지 이름 · 굿즈샵</title>
  <link rel="stylesheet" href="css/style.css">
  <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
  <script src="js/config.js"></script>
  <script src="js/cart.js"></script>
  <script src="js/common.js"></script>
</head>
<body>
  <nav id="nav" class="nav"></nav>
  <main class="container">
    <h1>페이지 제목</h1>
    <p class="subtitle">이 페이지에서 무엇을 하는지 한 문장으로.</p>
    <!-- .card 안에 내용 -->
  </main>
  <script>
    // 페이지 전용 코드. DB·사용자 값을 HTML에 넣을 땐 반드시 esc()
  </script>
</body>
</html>
```
- `<title>`은 `페이지 이름 · 굿즈샵` 형식 (홈만 `굿즈샵`).
- 좁은 폼 화면(로그인, 결과)은 `.container.container-narrow`.
- 새 페이지를 만들면 필요할 때 `js/common.js`의 `renderNav()` 메뉴에도 추가하고, `CLAUDE.md`와 `ARCH.md`의 페이지 목록을 갱신한다.

## 끝내기 전 체크리스트
- [ ] **[금지 1]** 이모지·아이콘이 하나도 없다 (허용 기호 `+ − × ·`만). 아래 명령으로 찾는다. 코드 주석(`//`, `/* */`, `<!-- -->`) 안의 `→`는 화면에 나오지 않으므로 괜찮고, 그 밖의 결과는 모두 고친다:
  `LC_ALL=C.UTF-8 grep -nP "[\x{1F300}-\x{1FAFF}\x{2300}-\x{23FF}\x{2600}-\x{27BF}\x{2B00}-\x{2BFF}\x{2190}-\x{21FF}\x{203A}\x{FE0F}]" *.html js/*.js css/*.css`
  DB 상품의 `emoji` 칸도 화면에 쓰지 않는다.
- [ ] **[금지 2]** 색 코드가 `css/style.css`의 `:root` 안에만 있다. 페이지에 `<style>` 태그·`style="color/background"`가 없다
- [ ] **[금지 3]** 같은 뜻에 다른 단어가 없다. 버튼은 "~하기", 상태는 "~ 완료", 알림은 "~했어요"
- [ ] 색 코드를 새로 쓰지 않고 `:root` 변수만 썼다
- [ ] 버튼은 `.btn` / `.btn-ghost` / `.btn-danger`뿐이고, 파란 버튼은 화면당 하나다
- [ ] 본문·버튼·입력칸 글씨가 16px 이상, 보조 글씨가 14px 이상이다
- [ ] 누를 수 있는 것은 모두 44px 이상이고, 주요 버튼은 48px 이상이다
- [ ] 버튼 글씨와 배경의 대비가 4.5:1 이상이다
- [ ] 모든 입력칸 위에 라벨이 있고, 잘못 입력하면 `setFieldError`로 그 칸이 빨개지며 이유가 나온다
- [ ] 375px 폭에서 가로 스크롤이 없고, 두 칸 배치가 한 칸으로 쌓인다
- [ ] 문구가 해요체이고 용어집 표현과 같다 (삭제 확인은 "삭제할까요?")
- [ ] 오류 문구가 한국어이고, 무엇이 문제인지와 해결 방법을 알려 준다
- [ ] 사용자·DB 값은 `esc()`로 감쌌다
